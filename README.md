# Каталог сыров — инструкция для продавца

Адрес сайта: **https://syr-dom.ru** (старый адрес `tulamax.github.io/katalog-syrov` перенаправляет сюда).

Сайт работает без сервера и без базы данных: это набор файлов, которые лежат на GitHub
(репозиторий `tulamax/katalog-syrov`) и показываются через GitHub Pages.
Покупатель выбирает сыры и вес, а заказ отправляет вам в WhatsApp, Telegram, MAX или по SMS готовым текстом.

Здесь описано всё, что вам может понадобиться менять. Никаких программ ставить не нужно —
только браузер и Google-таблица.

## 1. Google-таблица

Список товаров сайт берёт из вашей Google-таблицы:

**https://docs.google.com/spreadsheets/d/1gyVSHrFPf_UrdDuxYtx6XOVTiYEarkQYSVrpUgynSVM/edit**

Товары — на **первом листе** таблицы (первая вкладка внизу; как она называется — не важно).
Сайт уже знает адрес этой таблицы, ничего вписывать не нужно.

**Единственное, что нужно сделать один раз — открыть таблицу на чтение по ссылке.**
Пока это не сделано, сайт показывает встроенный каталог из файла `data/products.json`,
а не вашу таблицу.

1. Откройте таблицу по ссылке выше.
2. Справа вверху нажмите кнопку **«Настройки доступа»** (может называться «Поделиться»).
3. В блоке «Общий доступ» нажмите **«Ограниченный доступ»** и выберите **«Все, у кого есть ссылка»**.
4. Справа от этого выбора оставьте роль **«Читатель»** (не «Редактор» — иначе любой сможет менять цены).
5. Нажмите **«Готово»**.

Проверить, что всё сработало, просто: измените цену любого сыра и откройте сайт в новой
вкладке (лучше в режиме инкогнито) — цена должна обновиться в течение нескольких секунд.

**Если захотите другую таблицу.** Создайте её на [sheets.google.com](https://sheets.google.com),
импортируйте заготовку «Файл → Импортировать → Загрузить» из файла `data/sheet_template.csv`
этого репозитория (в нём все 53 сыра с описаниями; заготовку создаёт команда
`python tools/sheet_template.py`), откройте доступ как описано выше и вставьте id новой таблицы в
файл `js/config.js` в строку `sheetId: '…'` (id — длинная часть адреса между `/d/` и `/edit`).
После этого опубликуйте изменение (раздел 5).

## 2. Как менять ассортимент

Вы меняете цену в таблице — она меняется на сайте. Ничего публиковать не нужно.
Покупатель, который открывает сайт впервые, увидит новые данные сразу. Тот, кто уже заходил,
сначала на секунду-другую увидит прошлую версию каталога (телефон помнит её до суток, чтобы
каталог открывался мгновенно и при плохой связи), а затем страница сама подтянет свежую таблицу.

**Колонки таблицы** (первая строка — заголовки, менять их нельзя; порядок колонок не важен):

| Колонка | Что писать | Примеры |
|---|---|---|
| `id` | Номер товара. Уникальный, не меняется никогда — по нему сайт находит фото и помнит корзину покупателя | `1`, `54` |
| `Название` | Как товар называется на карточке | `Landana 1000 дн` |
| `Категория` | Одно из: `Твёрдые`, `Голубые`, `Мягкие`, `Козий`, `С добавками` (регистр не важен) | `Голубые` |
| `Описание` | Текст под названием. Можно с запятыми и переносами строк | `Гауда выдержки 1000 дней…` |
| `Цена за 100 г` | Число в рублях. Пусто, `0`, `—` или `по запросу` → на сайте «Цена по запросу» | `1250`, `1 250`, `1250,50` |
| `В наличии` | Пусто или `да` — есть; `нет` — товар показывается серым, заказать нельзя | `да`, `нет` |
| `Фото` | Пусто — берётся `images/{id}.jpg` из репозитория; или ссылка на картинку в интернете | `https://…/syr.jpg` |
| `Порядок` | Число: чем меньше, тем выше на сайте. Пусто — как идут строки в таблице | `10` |

**Как писать цену.** Копейки отделяются запятой: `1250,50` — это 1250 рублей 50 копеек.
Тысячи можно отделять пробелом: `1 250`. Запятая перед тремя цифрами тоже считается разделителем
тысяч: `1,250` — это 1250 рублей, а не «рубль двадцать пять». Знак `₽` или слово `руб.` писать
можно, они не мешают. Если в ячейке буквы (`1e3`, `дорого`) — сайт покажет «Цена по запросу».

**Как писать наличие.** «Есть» — это пусто, `да`, `есть`, `yes`, `1`, `+`. «Нет» — `нет`, `no`, `0`, `-`.
Любое другое слово (`мало`, `скоро`, `под заказ`) сайт на всякий случай считает как **«нет в наличии»**
(в консоли браузера при этом будет предупреждение) — так покупатель не закажет то, чего нет.

**Добавить новый сыр** — новая строка с новым `id` (возьмите следующий свободный номер, например 54).
**Убрать сыр** — удалите строку или напишите `нет` в колонке «В наличии» (тогда его видно, но не заказать).
**Временно поднять цену** — просто исправьте число.

**Что будет при ошибке.** Сайт спроектирован так, чтобы покупатель никогда не увидел «сломанный» каталог:

- Строка без `id` или без «Название» — просто пропускается.
- Две строки с одинаковым `id` — берётся первая.
- Непонятная категория — товар остаётся, но попадает в первую категорию («Твёрдые»).
- Непонятная цена (буквы) — показывается «Цена по запросу».
- Непонятное слово в «В наличии» — товар «нет в наличии».
- Лишняя или переименованная колонка — просто не читается (в консоли будет предупреждение с её названием).
- Таблица недоступна (закрыт доступ, нет интернета, в таблице ни одной правильной строки) —
  сайт молча показывает встроенный список из файла `data/products.json`. Покупатель ошибку не видит.
- Последняя удачно загруженная таблица запоминается в телефоне покупателя на сутки, поэтому
  даже при плохой связи он увидит актуальные цены.

**Запасной список — файл `data/products.json`.** Он используется, когда таблица недоступна.
Его можно править прямо на GitHub (карандаш «Edit» на странице файла), но нужно быть аккуратным
с кавычками и запятыми: одна лишняя запятая — и файл не прочитается. Раз в несколько месяцев стоит
перенести в него актуальные цены, чтобы «запасной» список не отставал от жизни.

## 3. Как добавить или заменить фото

Каждому товару соответствует картинка `images/{id}.jpg`, где `{id}` — номер товара:
у сыра с `id` 7 фото лежит в `images/7.jpg`.

**Вариант 1 — положить файл в репозиторий.**
Подготовьте фото 400×300 пикселей (горизонтальное, в формате JPG, желательно до 60 КБ) и
загрузите его в папку `images/` под именем `{id}.jpg` — на GitHub это «Add file → Upload files»
в папке `images`. Если файл с таким именем уже есть, новый его заменит. Версию кэша в `sw.js`
(раздел 5) при этом менять **не нужно**: новое фото — сразу у новых покупателей, а у тех, кто
уже заходил, — со второго открытия сайта.

**Вариант 2 — ссылка в таблице.**
Загрузите фото на любой сайт, который даёт прямую ссылку на картинку (адрес заканчивается на
`.jpg`, `.png` или `.webp` и начинается с `https://` — ссылки с `http://` браузер заблокирует),
и вставьте эту ссылку в колонку «Фото». Публиковать ничего не нужно.
Минус: если тот сайт удалит картинку, на карточке будет заглушка «нет фото».

Если файла с фото нет, карточка всё равно показывается — с заглушкой «нет фото».

## 4. Как поменять номер WhatsApp, Telegram и MAX

Все контакты и тексты — в одном файле `js/config.js`. Откройте его на GitHub, нажмите карандаш и
поменяйте значения между кавычками:

```js
whatsapp: '79161234567',   // номер в международном формате, без «+», пробелов и скобок
telegram: 'syrnaya_lavka', // имя пользователя Telegram без «@»
max: 'https://max.ru/syrnaya_lavka', // ссылка на ваш профиль в MAX
sms: '79161234567',        // номер для SMS (кнопка видна только на телефонах)
```

Ссылку на профиль MAX возьмите в приложении: Профиль → «Ссылка на профиль». MAX не умеет открывать
чат с готовым сообщением, поэтому кнопка «Написать в MAX» копирует текст заказа в буфер обмена и
открывает ваш профиль — покупателю остаётся вставить текст в чат (сайт подсказывает это).

Если оставить пустые кавычки `''`, соответствующая кнопка на сайте будет скрыта — так можно
оставить только один канал заказов.

В этом же файле:

- `shopName` — название в шапке;
- `sheetId` — id Google-таблицы (раздел 1); `sheetName` — имя листа с товарами, пусто = первый лист;
- `weightPresets: [100, 200, 500]` — кнопки быстрого выбора веса, в граммах;
- `weightStep: 50` — на сколько граммов меняют вес кнопки «+» и «−»;
- `minWeight: 50` — минимальный заказ одной позиции;
- `orderGreeting` и `orderFooter` — первая и последняя строки текста заказа.

Сохраните файл («Commit changes») и опубликуйте (раздел 5).

## 5. Как выкладывать изменения

Сайт показывает то, что лежит в ветке `main` на GitHub. Любая сохранённая на GitHub правка
(«Commit changes») публикуется автоматически, обычно за 1–2 минуты.
Если вы правите файлы у себя на компьютере, отправьте их командой `git push`.

**Важно про кэш.** Чтобы сайт открывался без интернета, телефон покупателя хранит копию файлов.
Чтобы после публикации все увидели новую версию, а не старую копию, в самом начале файла `sw.js`
нужно изменить строку с версией кэша — на любое новое значение. Удобно писать дату, а если в один
день публикуете несколько раз — добавлять номер:

```js
const CACHE_VERSION = 'v2026-09-20-2';
```

Правило простое: **поменяли `index.html`, `data/products.json`, что-то в папках `css/` или `js/`
(в том числе `js/config.js`) или сам `sw.js` — поменяйте версию**. Таблица и фото в этом правиле
не участвуют: цены из таблицы обновляются сами, а заменённое фото подхватывается со второго открытия.

Если у покупателя всё равно старая версия — попросите закрыть все вкладки сайта и открыть заново.

## 6. Домен syr-dom.ru

Домен `syr-dom.ru` куплен на Рег.ру 20.09.2026 (оплачен до 20.09.2027) и уже привязан:
в репозитории лежит файл `CNAME` с одной строкой `syr-dom.ru`, а в кабинете Рег.ру
(«Домены → syr-dom.ru → DNS-серверы и управление зоной») стоят записи:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `tulamax.github.io.` |

Эти записи менять не нужно. Сертификат HTTPS выпускает и продлевает GitHub сам.

**Что не забыть:**
- **Продление домена** — раз в год, около 06.09. Автопродление включено, но работает только при
  привязанной карте или положительном балансе в кабинете Рег.ру. Если домен не продлить, сайт
  перестанет открываться по адресу, но останется доступен по `tulamax.github.io/katalog-syrov`.
- **Идентификация владельца через Госуслуги** — Рег.ру требует её для всех доменов `.ru`
  (страница домена в кабинете → «Узнать подробнее»). Без неё ограничивают управление доменом.

**Если захотите другой домен:** купите его, замените строку в файле `CNAME`, у регистратора
пропишите те же записи, что в таблице выше, и на GitHub («Settings → Pages → Custom domain»)
дождитесь зелёной галочки и включите «Enforce HTTPS».

## 7. Если что-то пошло не так

- **Сайт показывает не мою таблицу, а старые цены.** Проверьте доступ к таблице («Все, у кого есть
  ссылка → Читатель», раздел 1), что товары на первом листе и что `sheetId` в `js/config.js`
  совпадает с адресом таблицы. Помните: у покупателя, который уже заходил, сначала на секунду
  показывается прошлая версия каталога, потом подгружается свежая таблица.
- **Кнопки отправки серые.** Покупатель не указал ни имя, ни телефон — так задумано.
- **Товар не заказывается.** В колонке «В наличии» стоит `нет` или непонятное слово.
- **Хочу вернуть как было.** На GitHub у каждого файла есть «History» — любую версию можно
  открыть и восстановить.

Проверка для тех, кто правит код: `npm install` (один раз), `npm test` запускает автоматические
тесты, `npm run serve` поднимает сайт локально на `http://localhost:8080`, `npm run e2e` — тесты
в браузерах.

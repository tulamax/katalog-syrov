# Каталог сыров — ТЗ этапа 1 («магазин без сервера»)

Статический сайт на GitHub Pages. Никаких фреймворков, бандлеров и шага сборки:
ES-модули в браузере, vanilla JS (ES2020), CSS без препроцессоров. Язык интерфейса — русский.
Целевые устройства: в первую очередь телефоны (iPhone Safari 15+, Android Chrome), затем десктоп.

## 1. Структура репозитория

```
index.html               оболочка страницы, разметка, <noscript>
css/app.css              все стили (mobile-first, CSS-переменные в :root)
js/config.js             CONFIG — единственное место с номером WhatsApp, Telegram, id таблицы, текстами
js/catalog.js            источник данных: products.json → (опционально) Google-таблица; парсер CSV; нормализация
js/cart.js               состояние корзины, localStorage, расчёт суммы, текст заказа, «последний заказ»
js/ui.js                 рендер каталога, поиск/фильтры, корзина, лайтбокс, кнопки заказа
js/app.js                точка входа: грузит каталог, инициализирует UI, регистрирует sw.js
data/products.json       каталог по умолчанию (fallback и источник истины для фото)
images/<id>.jpg          фото 400×300
sw.js, manifest.webmanifest, icon-*.png   офлайн-режим (уже есть, доработать под новую структуру)
CNAME                    домен (добавляется, когда домен известен)
tests/unit/*.test.js     node --test: catalog.js (CSV, нормализация), cart.js (сумма, текст заказа)
tests/e2e/*.spec.js      Playwright: chromium + webkit, сценарии из §7
tools/sheet_template.py  генерирует CSV-шаблон таблицы из products.json
README.md                инструкция для продавца (§8)
```

`index.html` не содержит данных товаров — только каркас. Карточки рендерит JS.
В `<noscript>` — текст «Для работы каталога включите JavaScript» и ссылка на сайт.

## 2. Данные

### 2.1 Модель товара (после нормализации, единая для всех источников)
```js
{
  id: number,            // уникальный, стабильный (ключ корзины)
  name: string,
  category: 'hard'|'blue'|'soft'|'goat'|'special',
  description: string,
  price: number|null,    // рублей за 100 г; null → «Цена по запросу»
  available: boolean,    // false → карточка показывается с пометкой «Нет в наличии», заказать нельзя
  photo: string,         // относительный путь 'images/1.jpg' или абсолютный https-URL
  sort: number           // порядок показа, по возрастанию
}
```
Категории и их русские названия — в `data/products.json` (`categories`).

### 2.2 Источники
1. `data/products.json` — грузится всегда первым, каталог рендерится сразу.
2. Google-таблица — если в `CONFIG.sheetId` непустая строка. Загружается через
   `https://docs.google.com/spreadsheets/d/{sheetId}/gviz/tq?tqx=out:csv&sheet={sheetName}`
   (таблица должна быть открыта «всем, у кого есть ссылка»). Таймаут 6 с (AbortController).
   Успех → каталог **заменяется** данными таблицы (товары, которых нет в таблице, исчезают).
   Ошибка/таймаут/невалидные данные → остаёмся на products.json, в консоль warning, пользователю ничего не показываем.
3. Успешно загруженная таблица кэшируется в `localStorage` (`catalog:sheet`, с timestamp) и при следующем
   открытии используется мгновенно, пока сеть не ответит (stale-while-revalidate). TTL 24 ч.

### 2.3 Формат таблицы (лист «Товары»), первая строка — заголовки, регистр и пробелы в заголовках игнорируются
| id | Название | Категория | Описание | Цена за 100 г | В наличии | Фото | Порядок |
- `Категория`: русское название из `categories` **или** код (`hard`…); сопоставление без учёта регистра.
- `Цена за 100 г`: число; пусто, 0, «—», «по запросу» → null. Допускаются «1 250», «1250,50».
- `В наличии`: пусто/да/yes/1/true/+ → true; нет/no/0/false/- → false.
- `Фото`: пусто → `images/{id}.jpg`; иначе как есть (URL или относительный путь).
- `Порядок`: число; пусто → порядок строк в таблице.
- Строка без `id` или без `Название` — пропускается с warning. Дубликат `id` — берётся первая строка.
- Парсер CSV: RFC 4180 (кавычки, запятые и переводы строк внутри кавычек, `""`), BOM, `\r\n`.
- Если после парсинга 0 валидных товаров — источник считается невалидным (fallback).

## 3. Конфигурация (`js/config.js`)
```js
export const CONFIG = {
  shopName: 'Каталог сыров',
  whatsapp: '',            // международный формат без «+», напр. '79161234567'; пусто → кнопка скрыта
  telegram: '',            // username без «@»; пусто → кнопка скрыта
  sheetId: '',             // id Google-таблицы; пусто → только products.json
  sheetName: 'Товары',
  currency: '₽',
  weightPresets: [100, 200, 500],   // граммы
  weightStep: 50,                    // шаг «+/−»
  minWeight: 50,
  orderGreeting: 'Здравствуйте! Хочу заказать:',
  orderFooter: 'Подтвердите, пожалуйста, наличие, цену и способ доставки.',
};
```
Все значения читаются только из CONFIG; в остальных модулях никаких «магических» номеров.

## 4. Корзина и заказ (`js/cart.js`)
- Состояние: `{ [id]: grams }` + данные покупателя `{ name, phone, address, comment }`.
- Сохраняется в `localStorage` (`cart:v1`) при каждом изменении; восстанавливается при открытии.
  Позиции, которых больше нет в каталоге или `available=false`, при восстановлении удаляются.
- Граммы: целое ≥ `minWeight`, округление до `weightStep` при вводе вручную (100.5 → 100, 130 → 150 по правилу
  ближайшего шага, 20 → minWeight). 0 или пусто → позиция удаляется.
- Сумма позиции = `price * grams / 100`, округление до рубля. Если у товара `price=null` — в сумму не входит,
  в тексте помечается «цена по запросу». Итог: «Итого: 1 234 ₽» + при наличии таких позиций «(+ позиции по запросу)».
- Текст заказа (формат фиксирован, покрыт юнит-тестом):
```
Здравствуйте! Хочу заказать:

• Landana 1000 дн — 200 г — 1 100 ₽
• Сантагюр — 100 г — цена по запросу

Итого: 1 100 ₽ (+ позиции по запросу)
Всего: 300 г

Имя: Анна
Телефон: +7 916 123-45-67
Адрес: ул. Ленина, 1
Комментарий: позвонить заранее

Подтвердите, пожалуйста, наличие, цену и способ доставки.
```
  Пустые поля покупателя не выводятся. Числа форматируются с пробелом-разделителем тысяч (`1 100`).
- «Последний заказ»: при нажатии любой из кнопок отправки текущая корзина сохраняется в `localStorage`
  (`lastOrder:v1`). Кнопка «Повторить прошлый заказ» видна, если он есть; восстанавливает позиции
  (только доступные) и данные покупателя.

## 5. Интерфейс (`js/ui.js`, `css/app.css`)
Сохранить текущий визуальный стиль (коричневая шапка `#3b2a1a`, фон `#f5f2ec`, акцент `#c8a05a`, карточки 2 в ряд на телефоне).

Карточка товара:
- фото (тап → лайтбокс на весь экран, закрытие тапом/Esc/свайпом вниз не обязателен), категория, название, описание;
- цена: «1 250 ₽ / 100 г» или «Цена по запросу»; «Нет в наличии» — карточка приглушена, управление скрыто;
- пресеты веса: чипы 100 / 200 / 500 г (из CONFIG) — тап ставит вес и добавляет в корзину;
- «−» / поле граммов / «+»; поле `type="number" inputmode="numeric" pattern="[0-9]*"`;
- кнопка «В корзину» / «✓ В корзине · 200 г» (состояние отражает корзину).

Шапка: название, подпись, поиск (по названию и описанию, без учёта регистра, debounce 150 мс),
чипы категорий (Все + категории), счётчик «в корзине N позиций».

Корзина (нижняя панель, как сейчас; на десктопе — боковая колонка ≥ 900 px):
- список позиций: название, граммы (редактируемые), сумма, удалить;
- итог;
- поля покупателя: Имя, Телефон (`type="tel"`), Адрес, Комментарий — все необязательны, кроме одного из Имя/Телефон
  для отправки (иначе кнопки отправки неактивны с подсказкой «Укажите имя или телефон»);
- кнопки: «Отправить в WhatsApp» (зелёная), «Отправить в Telegram», «Скопировать текст», «Повторить прошлый заказ», «Очистить»;
- textarea с текстом заказа (readonly) — остаётся, для тех, кто копирует вручную.

Кнопки отправки:
- WhatsApp: `https://wa.me/{whatsapp}?text={encodeURIComponent(text)}`.
- Telegram: `https://t.me/{telegram}?text={encodeURIComponent(text)}`.
- Открывать через `<a target="_blank" rel="noopener">` с href, который обновляется при каждом изменении корзины
  (никаких `window.open` из асинхронного кода — Safari блокирует).
- Перед переходом заказ сохраняется как «последний».
- «Скопировать»: `navigator.clipboard.writeText`, fallback — выделение textarea (`contentEditable` + `setSelectionRange`)
  + `execCommand('copy')`; результат показывать сменой текста кнопки на 1.8 с.

Пустые состояния: «Ничего не найдено» при поиске; «Корзина пуста» с подсказкой.
Доступность: кнопки с `aria-label`, лайтбокс с `role="dialog"`, фокус возвращается; контраст текста ≥ 4.5:1.
Производительность: 53 карточки рендерятся одним `innerHTML`/фрагментом, `loading="lazy"` у фото;
делегирование событий на контейнере; никаких перерисовок всего каталога при изменении корзины
(обновляются только затронутые карточки по `data-id`).

## 6. Офлайн (`sw.js`)
- Precache: `./`, `index.html`, css, js, `data/products.json`, manifest, icons.
- Изображения `images/*` и внешние фото: cache-first с записью в кэш при первом запросе (runtime cache `images`).
- Google-таблица (`docs.google.com`): network-only, в SW не кэшируется (кэш в localStorage, §2.2).
- Версия кэша — строка `CACHE_VERSION` в начале `sw.js`; менять при каждом деплое (в README — правило).
  Старые кэши удаляются в `activate`. Стратегия для precache — stale-while-revalidate.
- Если SW недоступен (file://, http) — сайт работает без него.

## 7. Тесты
Unit (`node --test tests/unit`): парсер CSV (кавычки, переводы строк, BOM), нормализация строк таблицы
(все варианты «В наличии», цен, категорий, фото по умолчанию, дубликаты id), округление граммов,
расчёт суммы, текст заказа (точное сравнение со строкой из §4), восстановление корзины с удалением
пропавших позиций.
E2E (Playwright, chromium + webkit, viewport 375×812 и 1280×800; локальный статический сервер):
1. каталог рендерится, 53 карточки, фото загружены (naturalWidth>0 у первых 4);
2. поиск «горгонзола» → только горгонзолы; фильтр «Голубые» → N карточек;
3. пресет 200 г → позиция в корзине, сумма/«по запросу»; «+» → 250; ввод 130 → 150; ввод 0 → удалена;
4. перезагрузка → корзина восстановлена;
5. без имени/телефона кнопки отправки disabled; с телефоном — href wa.me содержит закодированный текст с позициями и телефоном;
6. «Повторить прошлый заказ» после «отправки» восстанавливает корзину после очистки;
7. лайтбокс открывается/закрывается;
8. с невалидным sheetId (сеть заблокирована через route) каталог показывает products.json без ошибок в консоли уровня error;
9. страница без консольных ошибок на всех сценариях.
Скрипт запуска: `npm test` (unit) и `npm run e2e`; `package.json` с devDependency `@playwright/test`.

## 10. Уточнения по итогам ревью (имеют приоритет над разделами выше)

Данные и корзина
- §2.3 «В наличии»: «да» = пусто/да/yes/1/true/+/есть; «нет» = нет/no/0/false/-; любое другое непустое значение → `false` + `console.warn` (безопаснее для продавца).
- §2.3 «Цена»: запятая — десятичный разделитель только если после неё 1–2 цифры и в строке нет точки («1250,50» → 1250.5); иначе запятая/пробел/точка между группами по 3 цифры — разделитель тысяч («1,250» → 1250, «1 250» → 1250). Символы валюты («₽», «р.», «руб») отбрасываются. Если после очистки остаются буквы (в т.ч. «1e3») → `null` + warn. Нераспознанный заголовок колонки → warn с его текстом.
- §2.2: кэш листа хранит `sheetId`; читается только если `CONFIG.sheetId` непустой и совпадает; возраст считается как `Math.abs(now - ts)`. `CONFIG.sheetName = ''` означает первый лист таблицы (параметр `sheet` не передаётся).
- §3: никаких переопределений CONFIG из URL (`?sheet=` удалить). В e2e конфиг подменяется через `page.route('**/js/config.js')`.
- §4: если все позиции «по запросу» — строка `Итого: цена по запросу` (без «0 ₽»); та же строка в панели корзины. Формат персиста корзины — `{items: [[id, grams], …], customer}` (порядок добавления); старый формат-объект читается.
- `setGrams(id, …)` игнорирует id, которых нет в каталоге или `available=false`; `getLines()` не отдаёт недоступные; метод `add` удалить из контракта (UI использует `setGrams`). Добавить `clearItems()` — очищает позиции, оставляя данные покупателя; кнопка «Очистить» в UI вызывает его.
- `normalizeGrams('1 000')` → 1000 (пробелы убираются до Number). UI передаёт в `setGrams` строку из поля как есть; если значение не число (`'1e'`, `'-'`, пусто при фокусе) — корзина не меняется, поле возвращается к текущему значению при blur.
- `hasLastOrder()` — true только если в прошлом заказе есть хотя бы одна доступная позиция; результат кэшируется в памяти и обновляется при saveLastOrder/setProducts. «Повторить прошлый заказ» при непустой корзине — `confirm('Заменить текущую корзину прошлым заказом?')`.
- `readRecord`: `items` принимается только как массив пар или объект; иное → пустая корзина.

Интерфейс
- Все поля ввода (`.qty-row input`, `#cart-items li input`, `#order-text`, поля покупателя, поиск) — `font-size: 16px` (iOS-зум).
- `index.html`: `apple-mobile-web-app-status-bar-style` → `default`; добавить `mobile-web-app-capable`; `<details>` без атрибута `open` в разметке — состояние ставит JS (десктоп открыт, телефон свёрнут); на десктопе `summary` не фокусируем (`tabindex=-1`) и обработчик `toggle` не даёт закрыть.
- Нижняя панель: `max-height: 62vh; max-height: 62dvh`; `body` получает `padding-bottom` = фактическая высота панели (обновлять на `toggle`, `ResizeObserver` панели); `.card { scroll-margin-top: 150px }`; на ≤ 360 px ширины при открытой панели скрывать `.note` и `.cart-status`.
- Клавиатура iOS: при `focusin` внутри `#cart-bar` на телефоне панель переводится в поток (класс `cart-bar--editing`: `position: static`, `max-height: none`) и поле прокручивается `scrollIntoView({block:'center'})`; на `focusout` (если фокус ушёл из панели) — обратно. `<meta name="viewport" … interactive-widget=resizes-content>`.
- Контраст: `--c-tag: #7a5c2e`, `--c-muted-2: #6e5f4a`, `#777` → `#6a6a6a`; WhatsApp-кнопка фон `#128C7E`, Telegram `#0b6fa4`, текст белый.
- `aria-live`-узлы (`#cart-count`, итог, бейдж) обновляются только при изменении строки; «✓ Скопировано» дублируется в `role="status"` visually-hidden span.
- Лайтбокс: `inert` на остальном содержимом (`.layout`) на время открытия + ловушка Tab; блокировка прокрутки фона через `body.lightbox-open { position: fixed; top: -scrollY }`; `aria-labelledby` на подпись; `state.lightboxOpener` сбрасывать при `renderCatalog`.
- DOM-порядок: `<aside id="cart-bar">` перед `<main>`; визуальный порядок через CSS; skip-link «К корзине» первым элементом `body`.
- Disabled-ссылки отправки: `aria-disabled="true"`, остаются в табуляции, `aria-describedby="send-hint"`; `#send-hint` всегда в DOM (visually-hidden, когда не нужен).
- «+»/«−» при фокусе в поле граммов берут за базу значение поля; после `setGrams` значение поля всегда синхронизируется с корзиной.
- `.remove` в корзине — цель ≥ 44×44 px; `-webkit-tap-highlight-color: transparent` на `.card, button, .btn, summary`; `touch-action: manipulation` на `a.btn, summary`.
- `img.photo` при ошибке загрузки → встроенный SVG-плейсхолдер (data-URI), без сетевых запросов.
- `@media print`: панель корзины и шапка в потоке.
- manifest: `"purpose": "any maskable"` у иконок, `"id": "./"`.
- Обновление SW: `skipWaiting` + `clients.claim` остаются; `app.js` по `controllerchange` показывает ненавязчивую плашку «Доступна новая версия — Обновить» (кнопка делает `location.reload()`), автоматически не перезагружает.

Service worker
- Имена кэшей с префиксом `katalog-syrov-`; в `activate` удалять только кэши с этим префиксом (origin `tulamax.github.io` общий с другими проектами).
- Фото — отдельный кэш `katalog-syrov-images` без версии: cache-first + фоновая ревалидация (обновлённое фото под тем же именем видно со второго открытия). Кэшировать только ответы с `res.ok` (opaque не кэшировать). README: смена фото не требует смены версии.
